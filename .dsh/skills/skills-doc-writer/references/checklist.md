## 0. 流程（没走完这一步，下面四组不用看）

- [ ] 先出了三级大纲文件（`##`~`####`），不是直接写正文「大纲」
- [ ] 每条三级标题下都有 `<mark>` 黄色标记，写明了引用哪份文件的哪个章节的哪些内容「大纲」
- [ ] 标记粒度到章节号 / 页码 / 条号 / chunk，没有"《招标文件》""同上""见前文"「大纲」
- [ ] 写每一节前都按标记把原文调出来读过，不是凭记忆写
- [ ] 用过的标记都已升级成正式引用记录（资料名称、章节/页码、采用内容、出处）
- [ ] `【待补】` 已清零，或已转进待确认事项章节「大纲」
- [ ] 按 D1 的编写顺序推进（先范围/职责、角色/业务、数据对象、架构，最后回头写目标与概述），不是从第 1 章顺着写
- [ ] 图表清单已建立，写到对应章节时同步出图；未出图的标了"待出图"
- [ ] 缺参数的地方都先问过用户，不是自己绕过去的
- [ ] 没有任何一处用"能力/流程/参数项/测算方法"包装的空话顶替缺失的参数
- [ ] 待确认事项集中成文末独立章节，每项有影响章节、责任方、需取得的资料、最迟确认节点
- [ ] 正文里没有散落的"待定""视情况"，都回指待确认事项章节
- [ ] 正文是分章写的，写完的章节与大纲一致；中途改过大纲的，已写章节也回改了
- [ ] 大纲连续 2-3 章不必再改，才收尾（不是边写边改到最后一刻）
- [ ] 交付正文里没有残留 `<mark>` 标记，来源已按引用格式标注

## A. 内容与依据

- [ ] 每个结论后面有依据：用户材料、知识库检索结果、公开标准，或明确标注的假设（三者都不是的，删）
- [ ] 没有「业界普遍认为」「专家指出」这类不具名归因
- [ ] 没有编造的引用：标准编号、文件名、URL、数据来源都核实过（核实不到的已移入待确认清单）
- [ ] 所有数字能追溯到出处；没有出处的数字一个都不留（不许标成"估算"糊过去，要么问用户要么挂待确认）
- [ ] 没有为了填满章节而写的"因为没有数据所以写得泛"的段落
- [ ] 需求与方案逐条对应：需求列了几条，方案就覆盖几条，未覆盖的写明原因
- [ ] 建设范围边界清楚：写了"不做什么"（不替换的存量系统、不改造的范围）
- [ ] 关键结论给出了成立条件（如"在并发≤2000、响应≤2s 条件下成立"）
- [ ] 假设与前提显式列出，并写了假设不成立时的退路
- [ ] 遗留问题、未决事项有责任人和关闭时间
- [ ] 全文数字自洽：概算表、人力表、进度表、正文里的同一数字一致
- [ ] 术语、系统名、角色名、称谓全文唯一（同一事物不换名字）
- [ ] **每 300 字至少 1 个本项目专有事实**（专有名词、数字、日期、系统名、场地）「扫描」

## B. 文风与 AI 痕迹

- [ ] 逐段做过删除测试：删掉后信息不受影响的句子已删
- [ ] 没有任何句子能换个行业照样成立（标准条款引用除外）
- [ ] 禁用词表 §2.1 清零；§2.2 的词都有具体化处理「扫描」
- [ ] 句长长短交错，没有连续 3 句长度相近；超 80 字的句子已拆「扫描」
- [ ] 破折号 ≤1 处/千字，单行不超过 1 处「扫描」
- [ ] 加粗 ≤5 处，正文无 emoji、无感叹号「扫描」
- [ ] 没有段末总结句（"综上所述""由此可见""从而实现了"）「扫描」
- [ ] 「不是……而是……」全文 ≤2 次；「首先/其次/最后」没有机械使用「扫描」
- [ ] 段落长度有起伏，至少一段只有一句，至少一节明显更短「扫描」
- [ ] 没有立场真空句（"各有优缺点""因人而异"）——要么给判断，要么给条件
- [ ] 没有自赏句和假金句（"X 不是工具，而是镜子"）
- [ ] 全文没有助手残留（"以下是……""希望对你有帮助"）与未替换占位符（`XX公司`、`[项目名称]`）「扫描」

## C. 体例与格式（正式文档）

- [ ] 层级序号规范：一、→（一）→ 1. →（1），无 `一.`、`1、`、半角括号混用
- [ ] 数字用法符合 GB/T 15835：计量用阿拉伯数字，概数用汉字且数字间不加顿号，年份不简写，数值范围带单位
- [ ] 单独成行的标题结尾不加句号、不加冒号
- [ ] 表格只承载对比类信息，没有把一句话能说清的内容做成表
- [ ] 图表有编号与题注，正文有引用（"见下表"指向的表确实在附近）
- [ ] 图表清单里的图都已出图，每张图能替代一段说明性文字，不是只有框没有关系
- [ ] 需要交付 Word 时，已用 docx 工具生成并核对过格式

## D. 评审风险（投标/申报/评审类必查）

- [ ] 招标文件或申报通知的章节要求逐条对齐，无缺项、无自创顺序
- [ ] 实质性条款（★/▲）逐条响应，零负偏离，且给出量化证据
- [ ] 有技术响应/偏离表，每条对应招标文件的具体条款号
- [ ] 评分项在正文里都有对应小节，标题与评分项措辞一致
- [ ] 全文无「待定」「视情况」「按甲方要求」式空白响应
- [ ] 无「完全满足」「零风险」「国内领先」「100% 可靠」等无依据的绝对表述
- [ ] 技术指标带数值和单位，不用「高性能」「领先水平」替代
- [ ] 有进度计划（关键路径/里程碑）、人力配置（角色+人月）、验收标准、风险与应急
- [ ] 承诺内容有支撑：写进承诺的响应时限、到场时限、备件、培训场次，都是能兑现的

## 交付说明（随文档一起给，可短）

1. **来源与引用清单**：哪一段用了哪份材料——资料名称、章节/页码、采用内容、URL 或出处
2. **待确认事项**：长文档已成文末独立章节（影响章节、责任方、需取得的资料、最迟确认节点）；短文档列成同样结构的表
3. **图表清单**：编号、图名、所在章节、表达的关系；未出图的标"待出图"
4. **未覆盖项**：用户要求但材料不足、本次没写的部分，直说没写
5. **扫描结果**：`outline-check.mjs` 与 `doc-lint.mjs` 的严重项清零，提示项逐条说明判断结论（保留 / 已改 / 属误报）
